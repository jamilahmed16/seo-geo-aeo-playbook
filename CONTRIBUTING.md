# Contributing

Corrections and improvements are welcome.

## How

1. Open an issue using the correction template, or fork the repo and open a pull request.
2. Keep changes focused: one topic per pull request.
3. Support claims with a source or first-hand experience. Never add invented metrics or results.
4. Do not include client names, private data or credentials.
5. Run markdown lint locally if you can: `npx markdownlint-cli2 "**/*.md"`.

## Style

- Plain, direct language. Short sentences.
- Use commas, colons and periods instead of em-dashes.
- No emojis.
- Tables for comparisons, checklists for gates.
